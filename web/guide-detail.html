一、先看懂幾個名詞

以下說明會用到這幾個詞,先定義清楚:

名詞意思
水位池(桶)一個蓄水的桶子。玩家每轉下注,系統依設定比例往桶裡加一點水;水累積到一定程度就發獎,並從桶裡扣掉發出去的金額。同一個遊戲會有好幾個桶,各自負責不同大小的獎。
貢獻率每一轉往某個桶加多少水,以「注額的百分比」表示。所有桶的貢獻率加總 = 該注額的理論回報率(98% 或 97%)。
出獎範圍這個桶負責哪一段獎金,例如「5~10 倍」。
門檻水要累積到多少才發獎。部分方案的門檻在每次發獎後會重新抽一個隨機值。
個人池 / 全域池個人池 = 每位玩家自己一組桶,只吃自己的注、只發給自己;全域池 = 同一注額的所有玩家共用一組桶。
單位計帳桶裡裝的不是金額而是「單位」。$1 與 $10 的玩家每轉加同樣的單位數,但領走 1 單位時,$10 玩家拿到的錢是 $1 玩家的十倍。
改判先用原本的機率表抽出結果,再看桶裡的水夠不夠付;不夠就把這局改成沒中獎。
強制發獎某個桶的水滿到上限時,系統重複抽機率表,直到抽出落在這個桶範圍內的獎,然後發出去。
預灌建桶當下先裝一些水進去,免得玩家一開始等太久。裝多少由「預灌比例」決定。
出廠狀態表先在離線環境把系統跑很久(500 萬轉),把當時每個桶的狀態存成快照;正式上線直接從這個狀態開始,等於「機台已運轉一段時間」。
玩家狀態追蹤層記錄每位玩家的連輸長度與近期回報率,達到條件時直接為他發一個獎(從原有的桶扣款)。僅進1 / 進2 使用。

二、代號對照與各方案的做法

二階一階實際做法
ALPHAC純隨機:直接抽機率表,抽到什麼就是什麼,沒有桶、沒有干預。等同目前線上的做法,作為對照組。
BRAVOE先抽再檢查:每轉照常抽機率表;抽中獎後檢查對應的桶付不付得起,付得起照發、付不起把這局改成沒中獎。另外,某個桶滿到上限時會強制發獎(重複抽表直到抽出該桶範圍內的獎)。每個注額各一組桶。
進1 / 進2 另加一層玩家狀態追蹤(規則見第三節)。
DELTAH個人桶 + 全域桶:82% 的錢進每位玩家自己的桶(負責小獎),18% 進全服共用的桶(負責大獎)。不以機率表決定輸贏,完全看桶裡的水有沒有到門檻。
OSCARF全服共用桶:每個注額一組桶,全服玩家一起加水,誰把水推過門檻誰得獎。不以機率表決定輸贏,只看門檻。
TANGOG三注額共用一組桶 + 單位計帳:流程與 BRAVO 相同(先抽再檢查),差別在 $1/$5/$10 共用同一組桶,且桶裡記的是「單位」而非金額。
進1 / 進2 另加一層玩家狀態追蹤(規則見第三節)。

三、六組資料的差別

參數組參數版本開機方式
基1基準版出廠狀態表(已運轉一段時間的狀態)
基2基準版(同基1)預灌(全新啟動)
特1特化版出廠狀態表
特2特化版(同特1)預灌
進1特化版 + 玩家狀態追蹤層出廠狀態表(與特1 同一份快照)
進2同進1預灌

每一組的數字後綴一律代表開機方式:奇數 = 出廠狀態表、偶數 = 預灌。 進1 / 進2 的桶參數與特化版完全相同,出廠狀態表也直接沿用特化版的快照 (暖機時沒有玩家,那一層不會啟動,桶的變化規律因此與特化版一致), 因此 特1↔進1、特2↔進2 之間的差異可直接歸因於那一層。 本次只在 BRAVO 與 TANGO 上實作這一層,其餘三套方案沒有這兩組資料,儀表板上壓灰。

出廠狀態表的規則

  • 離線暖機 500 萬轉,匯出每個桶的三項狀態:目前水位、下次要發的獎金額、下次的門檻
  • 上線載入後純走規則;帳務的起算基準 = 出廠時的水位總和
  • 本次模擬每個批次各用一份獨立快照。原因:快照固定了各桶的首個門檻,若所有批次共用同一份,各桶的「第一次發獎」會落在相同局數、金額也相同
  • 各方案的水位變化規律不同,快照不能互相共用,需各自暖機產出
  • 兩個例外:DELTA 的個人桶由每位玩家新建,改為建桶時各自暖機 1 萬轉;TANGO 三注額共用一組桶,只需一份快照

預灌的規則

  • 公式:起始水位 = 隨機取值[出獎上限, 門檻上限] × 預灌比例。取值區間在「上限段」,不是從零開始
  • 比例:負責 100 倍以上大獎的桶一律 0.35;其餘依出獎上限由大到小,最小的三個桶 0.8、中段 0.65
  • $10(大額盤)的預灌比例分兩層訂,依據是「剩餘距離」。 剩餘距離 =(發獎線 − 目前水位)÷ 每轉加水量,也就是一個桶「還要多久發下一次獎」。 長期運轉時這個量有穩定的平均值,可由桶的循環規則直接算出。
    • 負責 50 倍以上大獎的桶:預灌比例訂為「使起始的剩餘距離等於長期運轉的平均值」, 本次為 0.51~0.52。這樣全新啟動的機台,大獎的首次出現時機與已運轉一段時間的機台相同
    • 負責 50 倍以下獎項的桶:預灌比例訂為「使起始水位等於長期運轉的平均水位」, 本次為 0.56~0.99。長期運轉時每位玩家的桶各處於不同進度,其中一批接近發獎線, 因此開局本來就會有一批小獎;對齊平均水位保留這個特性
    兩層的差別在於對齊的對象不同:大獎桶對齊「距離」(管時機)、小獎桶對齊「水位」(管手感)。 此規則僅適用於 $10;$1 與 $5 全部桶皆依上一條的通用比例。
  • 預灌只能對準各桶的平均水位,無法同時對準「水位與門檻的組合狀態」,因此分段回報率會呈現「前段偏高 → 中段回收 → 後段收斂」。要讓每一段都平穩,只能使用出廠狀態表
  • DELTA 特化版另有新手加水:新玩家建桶時,把負責小獎的特色桶水位墊高到接近發獎線 (只墊原本低於該線的桶,已經高於的不動),讓第一次特色玩法很快出現。 墊上去的水不是額外給的——系統會從這位玩家自己「水最多的桶」扣回同樣的量 (那些桶要累積很久才發一次獎,短期內本來就不會發,扣了不影響開局節奏)。 因此玩家的起始總水量不變、長期回報率不變,改變的只有「哪個獎先來」的順序。 $1 加在 Respin 小獎桶(比例 0.95)、$5 加在輪盤小獎桶(0.90)、$10 不加

玩家狀態追蹤層的規則(進1 / 進2)

  • 追蹤的內容:每位玩家的目前連輸長度,以及最近 200 局的回報率(滾動視窗,不是終身累計)
  • 觸發條件(本轉將以沒中獎收場時檢查,滿足其一即觸發):
    • 連輸達門檻。門檻不是固定值,每一段連輸重新抽一個 8~13 的隨機數
    • 最近 200 局的回報率低於 74%。此條件另有三道限制:至少已玩 30 局、 距上次觸發至少 22 局(冷卻)、且只接受 5 倍以上的獎
  • 發獎方式:重複抽機率表,直到抽出一個「負責它的桶付得起」的獎,然後發出去, 並從那個桶扣款。不設專用桶,錢一律來自原有的桶
  • 只認主遊戲的獎:重抽時跳過 Respin 與輪盤的結果。 若從特色桶扣款,那些桶的水被取走後,自然的特色中獎會被改判,特色觸發率(2% / 1.5%)就會失真
  • 回報率如何維持:因為錢來自原有的桶、沒有新錢產生,總回報率自動守恆, 不需要為這一層切預算。代價是它會排擠自然中獎——被排擠的部分表現為改判次數上升
  • 兩個設計上的取捨,理由如下:
    • 連輸門檻用區間隨機而非固定值:固定值會讓玩家歸納出「連輸第 N 局必定有獎」的規律
    • 回報率用滾動視窗而非終身累計:若以終身回報率為條件,而報表畫的也是終身回報率, 分布圖會在門檻以下出現一條垂直的邊(門檻以下沒有任何玩家)。 改用滾動視窗後兩者脫鉤,左尾維持自然的緩坡

四、採用各方案的前置作業與額外成本

本節回答:若決定採用某方案,上線前要準備什麼、營運中要多付什麼。四個參數組的前置作業不同,分列於各表。
所有含桶的方案(BRAVO / DELTA / OSCAR / TANGO)都有以下共通項:桶狀態需持久化與備援、參數需版本管理、上線前需長期模擬驗證。

ALPHA

項目內容
前置作業無。四個參數組皆為同一做法的複製,僅為使儀表板格子完整。
額外成本無。即現行做法。

OSCAR

項目內容
共通每個注額一組桶參數(本次 18 條);伺服器需保存每個注額的桶狀態(全服共用一份),每轉讀寫。
基1 / 特1需建立出廠狀態表產製流程:離線模擬 → 匯出快照 → 上線載入;快照需版本管理。可預先產製多份、上線隨機挑選。
基2 / 特2不需快照;全新啟動時前段回報率偏高。
額外成本全服共用狀態的併發寫入需處理(鎖或原子操作);多機部署需共享狀態儲存。不需保存任何玩家個人資料。

DELTA

項目內容
共通兩套桶參數(個人 / 全域);每位玩家的個人桶狀態必須入庫並跨連線接續——儲存量 = 玩家數 × 桶數,每轉需讀寫該玩家的狀態。玩家狀態永久保留,不設過期或重置。
基1 / 特1全域桶需出廠狀態表;個人桶另需預先產製一批個人起始狀態快照,新玩家隨機領取一份。
基2 / 特2個人桶與全域桶皆用預灌,不需任何快照;新玩家前段回報率偏高。
特1 / 特2 另加新手加水機制:需標記哪些桶適用,並實作兩段邏輯——(1) 只墊高原本低於發獎線的桶;(2) 從同一位玩家水最多的桶扣回等量的水,維持總水量不變。
額外成本五個方案中儲存與讀寫規模最大(每位玩家一組狀態)。

BRAVO

項目內容
共通桶參數(基準版 14 條 / 特化版 3~4 條:每個玩法類別一條寬桶 + 一條大獎桶);全服共用狀態(同 OSCAR)。
基1 / 特1需出廠狀態表,且必須以本方案自己的規律暖機產出。
基2 / 特2用預灌,不需快照。
特1 / 特2與基1 / 基2 的差別只在桶參數(特化版把桶合併成寬範圍以增加緩衝),不需保存任何玩家個人資料。
進1 / 進2 另加需保存每位玩家的狀態:目前連輸長度、本段連輸的門檻、冷卻剩餘局數,以及最近 200 局的投注與贏分(環形緩衝,每位玩家 200 筆)。此狀態需跨連線接續,每轉讀寫一次。桶參數與特1 / 特2 相同。
額外成本重複抽表的運算量:強制發獎需重複抽機率表直到抽出落在該桶範圍的獎。額外抽樣次數約為自然轉數的 418%(基準版)、36%(特化版)、66%(進1 / 進2);需設重試上限與冷卻機制。差異來自桶的寬度:桶越寬、水位緩衝越大,付不出來的情形越少,重複抽表也越少。

TANGO

項目內容
共通單一組桶參數(三注額共用,特化版 4 條),但每個注額各有一份貢獻率表;需實作單位計帳(加水記單位、發獎時乘上該玩家的注額)。桶狀態全服一份、不分注額。桶的出獎範圍必須取三個注額的聯集——範圍若只按單一注額訂,其他注額會出現「沒有桶負責」的獎金額而被全部改判。
基1 / 特1出廠狀態表只需一份(以三注額等比例的混合注流暖機)。
基2 / 特2用預灌,不需快照。
特1 / 特2同 BRAVO:差別只在桶參數,不需保存任何玩家個人資料。
進1 / 進2 另加同 BRAVO:需保存每位玩家的狀態並跨連線接續。另因三注額共用一組桶,這一層的支出會同時影響三個注額的可用水位。
額外成本重複抽表的運算量與 BRAVO 同量級。
各注額的回報率無法個別錨定:三注額共用同一組桶,實際回報率由當下的注額組成比例決定,財務上只能以總體檢視 (本批均等配置下,特化版的各注額回報率為 $1 97.6%、$5 98.5%、$10 95.6%,理論值分別是 98 / 97 / 97%)。
所有注額共用一組狀態,為全部方案中併發最集中之處。
$1 的機率表沒有輪盤,因此輪盤桶只由 $5 與 $10 的注加水、也只由他們領走。

六、各參數組的能力邊界

基1 / 基2 / 特1 / 特2 只使用各方案自己的原生機制(桶的範圍切法、貢獻率、預灌、 以及該機制原有的出獎規則),因此這四組回答的是「機制本身能做到什麼」。
進1 / 進2 額外加了一層玩家狀態追蹤,目前只在 BRAVO 與 TANGO 上實作; 其餘三套方案沒有這兩組資料,儀表板上會壓灰。

這個區分影響怎麼讀「連輸長度」與「單人回報率地板」兩欄:

  • 要讓某位玩家不落到某條線以下,系統必須知道這位玩家目前的狀況。 在原生機制裡,五套方案只有 DELTA 的個人桶天然具備這個資訊,其餘四套(含純隨機)都只有全服共用的桶
  • 共用桶的強制發獎給的是當下按下按鈕的那位玩家,不是特定玩家。 它能保證整體的分配,無法保證個別玩家的體驗
  • 同一個性質使共用桶無法提供「開局甜蜜點」:把某個桶的起始水位墊到接近發獎線, 第一次發獎由最先按下按鈕的那一位取得,同注額的其他玩家不受影響。 因此 $1 / $5 的首次特色時機,在共用桶方案上等於自然值
  • 進1 / 進2 的那一層是以玩家為對象的,所以它能同時處理連輸與回報率地板; 代價與前置作業列於第四節與下一節

跨方案比較時請注意:「$1 / $5 的首次特色時機」與「連輸保護、單人地板」的差異來自結構 (有沒有個人層級的資訊),不是來自調校程度。同一方案的 特1↔進1、特2↔進2 使用相同的桶參數、相同的出廠狀態表, 唯一的差別就是有沒有那一層,因此兩組數字的差異可以直接歸因於它。 但兩組是各自獨立跑的(隨機起點不同),差異中仍含抽樣雜訊,判讀時請看六個批次的共同傾向。

七、未納入本批資料的事項

把玩家狀態追蹤層平等加到另外三套方案上

本次只在 BRAVO 與 TANGO 上實作。這一層原則上可加在任何方案上,但另外三套各有一個必須先解決的問題:

  • OSCAR:不抽機率表,發獎完全由門檻決定。發獎路徑需改為「從對應的桶直接取一個獎」,而非重抽機率表
  • DELTA:有個人桶與全域桶兩種來源。從玩家自己的個人桶扣款會抵銷保護效果,因此應從全域桶扣
  • ALPHA:完全沒有桶可以扣款,這一層的支出會直接推高總回報率。 若要維持回報率錨定,需另備一份等比縮放的賠率表 (例如把回報率縮到 82%、移除 100 倍以上的大獎,把釋出的空間讓給這一層)
