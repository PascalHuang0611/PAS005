三、各方案的特別條例(摘要)

OSCAR(F)

  • 出廠狀態表條例:預灌與首個門檻獨立抽樣必然造成「開服瞬爆 → 蓄水低潮」,故改用離線暖機快照;落地必須建立出廠表產製流程
  • 特化 v7 = 基準結構 + HIT 溫和傾斜(自然優先);體感目標(首次特色、連輸、單人地板)結構性失守 —— 全域池無法個人化,這是 F 架構的能力邊界
  • 指紋:Bet10 單人地板 42%,比純隨機的 49% 更低 —— 全域顆粒讓不幸者更不幸

DELTA(H)

  • 切點取自原始分布,每類別「≥切點」約 18% 劃給全域;Bet1 主類無乾淨切點 → 雙生池補丁(同範圍拆全域/個人兩條)
  • 個人池穩態抽樣開機:每位玩家建池時獨立暖機 1 萬轉(= 隨機領一份個人出廠狀態);落地需預產個人狀態快照庫,玩家水位入庫接續
  • 特化 v9:newcomer_prime(新手特色池預灌,自費制——墊高的水從同組慢池扣回,不加碼 RTP)、拉底不砍頭語意;甜蜜點落點:Bet1 = RS1-P(0.95)、Bet5 = LW1-P(0.90)、Bet10 無(大額盤不做甜蜜點,首次輪盤 ≈52 轉的自然殘餘時間)
  • 成績:連輸 7/15/14、單人地板 82/70/68 —— 個人池是唯一能同時做到地板與連輸保護的架構

BRAVO(E)

  • 基準版:13 池(BIG = 倍率 ≥100 跨類別合一池 + 主遊戲各段 + RS/LW);強制補獎硬線 = 該池範圍最大倍率(永不超發)
  • 強制補獎用 rejection sampling(重骰機率表至落在該池範圍,上限 1000 次、失敗則冷卻 1000 轉)—— 獎項分布自動等於自然條件分布,盤面全為真抽
  • 特化版:大/中/小三池(82%)+ 補分池(18%);補分池支付「連輸達門檻」或「滿 30 局後個人 RTP 低於門檻」玩家的強制重骰
  • 連輸門檻每段連輸重骰 ∈ [8,13](固定值會形成「第 N 輸必得獎」的可抓規律);溢流閥:補分池超過營運上限則回流中/大池
  • 落地要求:需伺服器端追蹤每位玩家的累計 RTP 與連輸狀態(追蹤窗長、重置策略、跨 session 持久化為落地議題)

TANGO(G)

  • = BRAVO 機制 + 單位計帳 + 三 BET 共用池;Bet1 表無輪盤 → 其 LW 貢獻為 0,LW 池只由 $5/$10 灌與領
  • 出廠表單一一張(落地只能讀一張、真實混注比未知);水位被強制線硬夾,混注比變化後自我調節
  • 指紋一(基準版):跨注補貼 —— 不均等配置下 $10 玩家回報率衝到 100~107%(2 位大戶吃 100 位小戶灌的單位)
  • 指紋二(特化版):保底不對稱 —— $10 的 50 倍獎要抽 50 單位、共用池常付不起,大戶的大獎最容易被砍,而救援補回率與小戶相同

四、詳細版特有的欄位

欄位意義
來源出獎的水位池 ID;DELTA 附 G(全域)/ P(個人);20 = 補分池(BRAVO/TANGO 特化的救援)
殘值該次出獎後,該池剩餘的水位(倍率/單位)
原值被改判 0 分的局,其原始抽中的獎金額(僅 BRAVO/TANGO 會出現)
重試強制補獎或救援時,重骰機率表的次數

進階統計區塊:各池的觸發次數、已付總額、剩餘水位,池名後綴為(砍 N / 補 N / 補失敗 N)—— 砍 = 改判 0 分次數、補 = 強制補獎成功次數、補失敗 = 重骰達 1000 次上限而放棄的次數(該池隨後冷卻 1000 轉;無經濟影響,僅為重試紀錄)。

額外抽樣彙總:重骰總抽樣數 ÷ 自然轉數 = 落地時的額外 CPU 成本指標。 實測 BRAVO/TANGO 基準版約 418%(重骰量是自然轉的 4 倍多)、特化版 86~121%。這是 RNG 改判架構的隱性成本,選型時應納入考量。

五、解盲時的三個核心論點

  1. 個人保底只有個人池做得到:同一套「自然優先」的調校哲學下,DELTA 全面達標,OSCAR 全面失守,BRAVO/TANGO 靠玩家追蹤救援達成一半(連輸追平、地板只抬到一半)
  2. 共用池的兩面性:TANGO 基準版給大戶跨注補貼(107%),特化版追保底時卻讓大戶保護最薄——同一結構的一體兩面
  3. 預灌能補時間軸,補不了穩態分布:開局蓄水與首次特色可以用預灌/出廠表解決;命中率、連輸、單人離散只能在「達標強度 vs 自然度」之間取捨
