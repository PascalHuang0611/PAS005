怎麼讀
由上往下就是系統的執行順序。藍框是判斷、 綠框是發獎、紅框是沒中獎、 紫框是只有進1 / 進2 才執行的步驟。
兩個關鍵差異可以從流程圖直接看出來:ALPHA / BRAVO / TANGO 會抽機率表 (盤面是真的抽出來的),而 OSCAR / DELTA 不抽(先由水位決定金額,再回頭找一個吻合的盤面來顯示); 以及只有 DELTA 有「個人桶」,其餘方案的桶都是共用的。
所有方案都遵守「一轉最多發一個獎」:流程中只要有任一處發了獎,本轉就結束,不會再往下檢查。

ALPHA

純隨機——等同目前線上的做法,作為對照組。沒有桶、沒有任何前後處理。

抽機率表
依權重抽出一個盤面組合。第 4 輪若是 Respin 或輪盤,再抽該玩法的表並把分數相加。
照抽出的結果發獎
抽到什麼就是什麼,系統不做任何檢查或改動。

BRAVO

先抽機率表,再用桶的水位決定這個獎付不付得出來。每個注額各一組桶。

① 全桶加水
每一轉,依各桶的貢獻率往所有桶加水。加總 = 該注額的理論回報率。
② 抽機率表
與 ALPHA 完全相同的抽法,得到「原始結果」。
③ 原始結果有中獎嗎?
有中獎
找出負責這個獎的桶,水夠付嗎?
依獎金倍率與玩法類別對應到一個桶(100 倍以上的獎不分玩法,一律歸「跨類別大獎」桶)。
夠付
照原始結果發獎
從那個桶扣掉發出去的金額。玩家看到的盤面就是抽出來的那一個。
不夠付
改判為沒中獎
盤面改成一個 0 分的組合;水留在桶裡,之後由其他人領走。此局仍繼續往下走 ④。
沒中獎
往下走 ④
進1 / 進2 專屬
④ 玩家狀態檢查
本轉將以沒中獎收場時,檢查這位玩家的連輸長度與最近 200 局回報率(規則見解盲版指南第三節)。
達到條件,且重抽到一個「負責它的桶付得起」的主遊戲獎
發給這位玩家,本轉結束
從那個桶扣款。本轉在此結束,不再進行 ⑤ 的檢查——單轉最多發一個獎。
沒達到條件,或重抽 1000 次都沒有桶付得起
往下走 ⑤
重抽失敗會記錄一次失敗並讓這位玩家進入冷卻,避免桶枯竭時每轉白抽。
⑤ 有沒有哪個桶的水滿到它的出獎上限?
由編號小的桶優先;單轉最多發一個獎。
有
強制發獎
重複抽機率表,直到抽出落在那個桶範圍內的獎(上限 1000 次),然後發出去。因為獎是真的抽出來的,倍率分布自動等於該範圍的自然分布。
沒有
本轉沒中獎
顯示一個 0 分盤面。

TANGO

流程與 BRAVO 相同,差別在三個注額共用同一組桶,而且桶裡記的是「單位」而非金額。

① 全桶加水(記單位)
$1 / $5 / $10 的玩家共用同一組桶。每位玩家依「自己注額的貢獻率表」加水,單位 = 倍率。
② 抽機率表
抽這位玩家自己注額的機率表。
③ 原始結果有中獎嗎?
有中獎
找出負責這個獎的桶,單位夠付嗎?
桶的出獎範圍是三個注額的聯集——範圍若只按單一注額訂,其他注額會出現「沒有桶負責」的金額。
夠付
照原始結果發獎
從桶扣掉「倍率」的單位數,玩家實得 = 倍率 × 自己的注額。因此同樣扣 1 單位,$10 玩家拿到的錢是 $1 玩家的十倍——這就是跨注額補貼的來源。
不夠付
改判為沒中獎
單位留在桶裡,之後由任一注額的玩家領走。
沒中獎
往下走 ④
進1 / 進2 專屬
④ 玩家狀態檢查
條件與 BRAVO 相同。因為桶是三注額共用的,這一層的支出會同時影響三個注額的可用單位。
達到條件,且重抽到一個「負責它的桶付得起」的主遊戲獎
發給這位玩家,本轉結束
本轉在此結束,不再進行 ⑤ 的檢查。
沒達到條件,或重抽 1000 次都沒有桶付得起
往下走 ⑤
⑤ 有沒有哪個桶的單位滿到它的出獎上限?
該注額貢獻為 0 的桶會跳過(例如 $1 沒有輪盤,輪盤桶只由 $5 / $10 加水與領走)。
有
強制發獎
重複抽這位玩家的機率表,直到抽出落在那個桶範圍內的獎。
沒有
本轉沒中獎

OSCAR

不抽機率表。每個注額一組全服共用的桶,誰把水推過門檻誰得獎。

① 全桶加水
同注額的所有玩家往同一組桶加水。
② 有沒有哪個桶的水達到它的門檻?
門檻是每次發獎後重新抽的隨機值(範圍 = 該次要發的獎金額 ~ 門檻上限)。由編號小的桶優先,單轉最多發一個獎。
有
決定實際獎項
把該桶「這次要發的金額」對照真實賠付表,取不超過它的最接近獎項。
沒有
本轉沒中獎
顯示一個 0 分盤面。
③ 發獎、扣水、重抽
發出實際獎項並從桶扣掉同額;接著為該桶重新抽「下次要發的金額」與「下次的門檻」。盤面是從「賠率→盤面」字典裡挑一個吻合該獎金額的組合,不是抽出來的。

DELTA

不抽機率表。每位玩家有自己的個人桶(小獎),另有同注額全服共用的全域桶(大獎)。

① 兩組桶各自加水
82% 的貢獻進這位玩家的個人桶、18% 進全域桶。個人桶只吃自己的注、只發給自己。
② 全域桶有達到門檻的嗎?
全域桶優先於個人桶;達標多個時由編號小的優先,單獨發一個、不疊加。
有

由編號小的優先,單獨發一個。
有
